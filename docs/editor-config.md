# Shared editor settings

## .editorconfig

`.editorconfig` задає спільні правила форматування для всіх учасників команди.

### Global settings

- `charset = utf-8` — використовуємо UTF-8 для однакового кодування файлів.
- `end_of_line = lf` — однакові переноси рядків незалежно від ОС.
- `insert_final_newline = true` — файл закінчується порожнім переносом рядка.
- `trim_trailing_whitespace = true` — видаляються зайві пробіли в кінці рядків.

### C/C++

Для C і C++ використовуємо:

```ini
indent_style = space
indent_size = 4
tab_width = 4
```

Чотири пробіли є достатньо помітним, але компактним відступом для вихідного коду. `tab_width = 4` задає однакову ширину табуляції в редакторах, якщо вона використовується.

### Markdown and YAML

Для Markdown і YAML використовуємо:

```ini
[*.{md,yml,yaml}]
indent_style = space
indent_size = 4
```

Пробіли потрібні для передбачуваного відображення Markdown і коректної структури YAML. Узгоджене значення `indent_size = 4` залишено без змін.

## .gitignore

`.gitignore` визначає файли, які Git не повинен додавати до репозиторію. Це захищає локальні налаштування, секрети та згенеровані файли від випадкового commit.

- `.env` і `.env.*` — локальні змінні середовища, які можуть містити секрети.
- `__pycache__/` і `*.pyc` — згенеровані Python-кеші.
- `*.tar.gz` і `*.zip` — архіви, які не належать до текстової документації.
- `*.exe` і `*.out` — зібрані виконувані файли.
- `build/` і `dist/` — типові каталоги результатів збірки.
- `.vscode/` і `.idea/` — локальні налаштування IDE.

Ці правила достатньо вузькі: вони ігнорують відомі локальні або згенеровані артефакти, але не приховують довільні файли проєкту.
